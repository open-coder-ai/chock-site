# chock.sh

The source of [chock.sh](https://chock.sh): a static website for **chock**, a catalog of
policies (guardrails) for AI coding agents. The site lets a visitor browse the policies,
pick the ones they want, and get one `chock install --selection` command that builds a
Claude Code plugin from their picks on their own machine.

The site is generated by a Python script (`sitegen/`) from two pinned inputs:

- `.framework-ref` — the chock engine commit (only `sitegen/engine.py` imports chock);
- `.catalog-ref` — the chock-catalog commit the pages are built from.

It is plain HTML, CSS and vanilla JavaScript: no third-party requests and no cookies. The one
piece of backend is `functions/api/event.js`, a Cloudflare Pages Function that counts a few
anonymous actions (see "Site events" below). There is no deploy command; the local server binds
`127.0.0.1` only.

## Local setup and preview (bash)

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pip install "chock @ git+https://github.com/open-coder-ai/chock@$(cat .framework-ref)"
git clone https://github.com/open-coder-ai/chock-catalog .catalog
git -C .catalog checkout "$(cat .catalog-ref)"
python -m sitegen --catalog .catalog --out dist
python -m http.server 8000 -d dist      # open http://localhost:8000
pytest -q                               # unit tests (build the site themselves)
pytest -q tests/e2e                     # browser tests (after: python -m playwright install chromium)
ruff check . && ruff format --check .
```

**One command to build and serve locally:**

```bash
python -m sitegen serve --catalog .catalog            # builds into dist/, then serves http://127.0.0.1:8000
python -m sitegen serve --catalog .catalog --port 8080
```

`serve` runs the same build as `python -m sitegen --catalog .catalog --out dist`, then
serves `dist/` with the standard library's `http.server`, bound to `127.0.0.1` only.
It prints `Serving chock.sh locally at http://127.0.0.1:<port>/ (Ctrl+C to stop)`.
It is a local test server only: there is no deploy command, now or later, in this repo.

## `python -m sitegen` options

- `--catalog PATH`: required. A chock-catalog checkout at `.catalog-ref`; the build
  checks `git -C <catalog> rev-parse HEAD` and exits with code 2 on a mismatch.
- `--out PATH`: required for a build (default `dist` for `serve`). Emptied first,
  then written, with a `.sitegen-output` marker. The build refuses (exit 2) a path
  that is the repo root, the home directory, a filesystem root, an ancestor of
  the repo, or a non-empty directory without that marker.
- `--catalog-source URL_OR_PATH`: default `https://github.com/open-coder-ai/chock-catalog`.
  What the selection's `catalog.source` says. Tests pass the local `.catalog` path.
- `--release vX.Y.Z`: optional. Written to `catalog.release` when given; omitted otherwise.

## Site events

`data/analytics.yaml` lists every action the site counts and the ids each may carry
(plan AN-1). `track()` in `static/js/common.js` sends one with `navigator.sendBeacon` to
`/api/event` on the same origin, and never when the browser sends Global Privacy Control
or Do Not Track. On `localhost` and `127.0.0.1` it sends nothing unless the page URL has
`?track=1`. `functions/api/event.js` checks the event again and writes it to Workers
Analytics Engine (binding `EVENTS`). Without that binding it returns 204 and stores nothing.

Both sides import the allowlist from `functions/api/_allowlist.js`, which is generated
from the data; the build copies it to `dist/js/allowlist.js`. After editing
`data/analytics.yaml`, run `python -m sitegen allowlist`. The build refuses (exit 2)
a stale `_allowlist.js`.

## Home page data

The landing page (`sitegen/home.py`) reads these files; every count, label and
policy line on it is computed from the catalog at build time.

- `data/home.yaml`, under `landing:`: the page copy. The site shows no video.
- `data/demo.yaml`: one entry per terminal-demo tab, a policy id and a case id from
  that policy's eval suite. The build fails if the case is missing or does not
  expect a block.
- `data/incidents.yaml`: the incident table. The build fails on a policy id that is not
  a visible catalog policy.
- `static/js/home.js` (tabs) and `static/js/cost.js` (the cost calculator) are
  optional: without JavaScript the demo and the use cases render as lists and the
  calculator shows its formula and worked example as text.
