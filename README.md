# chock.sh

The source of [chock.sh](https://chock.sh): a static website for **chock**, a catalog of
policies (guardrails) for AI coding agents. The site lets a visitor browse the policies,
pick the ones they want, and get one `chock install --selection` command that builds a
Claude Code plugin from their picks on their own machine.

The site is generated by a Python script (`sitegen/`) from two pinned inputs:

- `.framework-ref` — the chock engine commit (only `sitegen/engine.py` imports chock);
- `.catalog-ref` — the chock-catalog commit the pages are built from.

It is plain HTML, CSS and vanilla JavaScript: no backend, no third-party requests, no
tracking. It is hosted on Cloudflare Pages (see "Deploy" below); the local server
binds `127.0.0.1` only.

## Local setup and preview (bash)

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pip install "chock @ git+https://github.com/open-coder-ai/chock@$(cat .framework-ref)"
git clone https://github.com/open-coder-ai/chock-catalog .catalog
git -C .catalog checkout "$(cat .catalog-ref)"
python -m sitegen --catalog .catalog --out dist
python -m http.server 8000 -d dist      # open http://localhost:8000
pytest -q                               # unit tests (build the site themselves)
pytest -q tests/e2e                     # browser tests (after: python -m playwright install chromium)
ruff check . && ruff format --check .
```

**One command to build and serve locally:**

```bash
python -m sitegen serve --catalog .catalog            # builds into dist/, then serves http://127.0.0.1:8000
python -m sitegen serve --catalog .catalog --port 8080
```

`serve` runs the same build as `python -m sitegen --catalog .catalog --out dist`, then
serves `dist/` with the standard library's `http.server`, bound to `127.0.0.1` only.
It prints `Serving chock.sh locally at http://127.0.0.1:<port>/ (Ctrl+C to stop)`.
It is a local test server only. Deploys run in CI; see "Deploy".

## Deploy (Cloudflare Pages)

`.github/workflows/deploy.yml` builds the site exactly as `ci.yml` does (the catalog at
`.catalog-ref`, the engine at `.framework-ref`) and uploads `dist/` to the Cloudflare
Pages project `chock-site` with the official wrangler action (Direct Upload, so every
build runs in this repo's pinned CI, never on Cloudflare).

- Only a push to `main` deploys, to the production branch `chock-site.pages.dev`.
  Pull requests never deploy and never see the Cloudflare secrets; before launch,
  `chock-site.pages.dev` is the staging site.
- The deploy job runs in the GitHub environment `production`, whose secrets only `main`
  can read.
- Without the secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`, the job still
  builds, prints `deploy skipped: Cloudflare secrets not set` and succeeds.
- `ci.yml` runs `actionlint` and `zizmor` on every workflow; every checkout sets
  `persist-credentials: false`.

**Response headers.** `deploy/_headers` is copied into `dist/_headers` by the build.
It sets, on every path, the page CSP plus `frame-ancestors 'none'`,
`X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` and
`Cross-Origin-Opener-Policy`. `tests/test_deploy.py` checks that its CSP equals the
`<meta>` CSP in `templates/base.html` plus `frame-ancestors`; change both together.
Asset names are not content-hashed, so `/css/*`, `/js/*`, `/img/*` and `/fonts/*` get a
short cache (`max-age=300`). There is no HSTS until launch.

**Not indexed before launch.** Every `*.pages.dev` URL is served with
`X-Robots-Tag: noindex`.

**Owner setup, once.**

1. Create a Cloudflare Pages project named `chock-site` with **Direct Upload**, not Git
   integration.
2. Create an API token with only **Account → Cloudflare Pages → Edit**; copy the Account ID.
3. In this repo's Settings → Environments, create `production` and set **Deployment
   branches** to `main` only.
4. Add `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as secrets of the `production`
   environment, never as repository secrets.
5. At launch: add the custom domain `chock.sh` in the Pages project, update DNS as
   Cloudflare shows, then set `launched: true` and add HSTS in a small PR.

Environment branch rules need a public repo, or a paid plan for a private one. Without
them, any workflow on any branch pushed to this repo can read the token.

**Rollback.** Pages keeps every deployment. In the Pages project → Deployments, pick an
earlier production deployment and choose **Rollback to this deployment**; or revert the
commit on `main` and let the workflow deploy again.

## `python -m sitegen` options

- `--catalog PATH`: required. A chock-catalog checkout at `.catalog-ref`; the build
  checks `git -C <catalog> rev-parse HEAD` and exits with code 2 on a mismatch.
- `--out PATH`: required for a build (default `dist` for `serve`). Emptied first,
  then written, with a `.sitegen-output` marker. The build refuses (exit 2) a path
  that is the repo root, the home directory, a filesystem root, an ancestor of
  the repo, or a non-empty directory without that marker.
- `--catalog-source URL_OR_PATH`: default `https://github.com/open-coder-ai/chock-catalog`.
  What the selection's `catalog.source` says. Tests pass the local `.catalog` path.
- `--release vX.Y.Z`: optional. Written to `catalog.release` when given; omitted otherwise.

## Home page data

The landing page (`sitegen/home.py`) reads these files; every count, label and
policy line on it is computed from the catalog at build time.

- `data/home.yaml`, under `landing:`: the page copy. `videos: []` at the top holds the
  home page's videos. **The video block ships hidden**: it renders only when `videos`
  has entries (`{title, href}`), and the board's placeholders and clip grid are not
  built at all.
- `data/demo.yaml`: one entry per terminal-demo tab, a policy id and a case id from
  that policy's eval suite. The build fails if the case is missing or does not
  expect a block.
- `data/incidents.yaml`: the incident table. The build fails on a policy id that is not
  a visible catalog policy.
- `static/js/home.js` (tabs) and `static/js/cost.js` (the cost calculator) are
  optional: without JavaScript the demo and the use cases render as lists and the
  calculator shows its formula and worked example as text.
